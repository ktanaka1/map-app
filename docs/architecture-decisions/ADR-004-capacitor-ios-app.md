# ADR-004: iPhoneアプリ化は Capacitor によるハイブリッド方式とする

日付: 2026-06-11
ステータス: 承認済み

## 背景

App Store での配布、ホーム画面からのフルスクリーン起動、ネイティブな操作感（スワイプ投票等）を目的に iPhone アプリ化を行いたい（プッシュ通知は現時点で不要）。

一方、本サービスの核心は「QRコード/リンクを受け取った参加者がインストールなしで即入室できる」ことであり、全員にアプリを要求する構成はビジョン（速さ）と衝突する。

検討した選択肢:

1. **PWA強化** — コストほぼゼロだが App Store に並ばない
2. **Capacitor** — 既存 React + Vite のビルドをネイティブシェルで包む。UIコード流用率ほぼ100%
3. **React Native (Expo)** — ネイティブUIだがクライアントの7〜8割を書き直し、以後ホスト用アプリと参加者用WebでUIコードベースが二重化する

## 決定

**Capacitor を採用し、「ホスト＝iOSアプリ／参加者＝Web」のハイブリッド構成とする。**

- クライアントは単一の React コードベースを維持し、Capacitor で iOS アプリとしてもビルドする
- 参加者の入室フロー（QR/リンク → ブラウザで即参加）は変更しない
- 「ネイティブな操作感」はスワイプ投票・ハプティクス等を Web 技術＋Capacitor プラグインで実装する。同じスワイプUIは Web 参加者にも提供される

## 影響・注意点

- **Apple審査リスク（Guideline 4.2 Minimum Functionality）**: WebViewラッパーと判定されるとリジェクトされうる。審査提出前にスワイプ投票・ハプティクス・カメラQR読み取り等のネイティブ価値を実装しておくこと
- **公開バックエンドが前提**: アプリは localhost に接続できないため、App Store 提出にはバックエンドのデプロイ（deploy-status メモ参照）が先行条件。開発中は Mac のローカルIP指定で実機確認可能
- **費用**: Apple Developer Program $99/年
- 将来プッシュ通知が必要になった場合も Capacitor プラグインで対応可能（RN移行は不要）
- React Native への移行は「ネイティブUIそのものが差別化要因になった」場合にのみ再検討する
