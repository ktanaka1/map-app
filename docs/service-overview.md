# サービス概要

## サービス名

（仮）map-app

## 何を作るのか

飲食店の予約とクチコミを管理するプラットフォーム。場所×キーワードで候補店を検索し、グループ全員がリアルタイムで投票してお店を1つに決める。

## ターゲットユーザー

飲食店を探す一般ユーザー（個人・グループ）。特に「その場にいる複数人で一緒にお店を決めたい」シーン。

## 大切にしたいこと

- **速さ**：ふと思い立ったときにすぐ検索結果が表示されること
- **精度**：キーワード×場所で的確な候補が出ること
- **クチコミの信頼性**：外部APIの実績あるクチコミを活用し、情報の質を担保すること

## ビジョン（最終目標）

複数人が外出先で各自のスマホを同期させ、画面を見ながら「いい」「よくない」を言い合い、全員の投票で最終的に1店舗に決まる——そんな体験のデファクトアプリになる。

## 主要ユーザーフロー

```
1. セッション開始（1人でも可）
   ├── [その場に全員集合] QRコードで参加 → 参加者確定
   └── [事前・遠隔]     リンクシェアで参加 → 参加者確定

2. キーワード入力フェーズ
   └── 参加者全員がキーワードを出し合う（追加・削除可能）

3. 検索
   └── 場所 × 全員のキーワードで飲食店を検索

4. 投票フェーズ
   └── 候補店を順に表示 → 各自がボタン（キープ／除外）で判定

5. 結果判定
   └── 全員の投票が揃ったら結果を表示 → 外部予約ページへ誘導
```

## MVP（最低限必要な機能）

1. **セッション参加**：QRコード（その場集合）＋リンクシェア（事前・遠隔）の両対応。1人参加も可能
2. **協調キーワード入力**：参加者全員がキーワードを出し合い、取捨選択できる
3. **場所×キーワード検索**：現在地やエリア＋収集したキーワードで飲食店を検索
4. **ボタンUI（キープ／除外）**：候補店に対して右ボタン（キープ）・左ボタン（除外）で絞り込む（スワイプ不要）
5. **リアルタイム同期投票**：複数人のスマホを同期し、全員の投票が揃った時点で結果を判定
6. **外部予約リンク**：決定したお店の外部予約ページ（食べログ・ぐるなび等）へ誘導
7. **クチコミ表示**：Google Places API等の外部APIからクチコミ・評価を取得して表示

## 仕様詳細（壁打ちで確定）

- **投票判定**: 全員一致でキープのみ通過。1人でもNGなら除外
- **複数キープ時の決定**（2026-06-10 確定）:
  - キープ1件ならそのまま決定店として表示
  - 2件以上なら一覧を表示し、**ホスト**が「評価順で1位に決定」か「決選投票」を選ぶ
  - 評価順: 評価（同点はレビュー数）で1位を決定店、残りは次点として併記
  - 決選投票: キープ店のみで1人1票の推し選び。最多得票で決定、同数は評価順で自動確定
  - ソロモードで複数キープ時は一覧から自分で1店を選ぶ
- **全滅フォールバック**（2026-06-10 更新）:
  - キープ1票以上の店があればキープ数最多の店を「最も支持されたお店」として提示
  - 全店キープ0（全員が全店除外）の場合は「全候補が除外されました」と正直に表示し、条件を変えた再検索へ誘導する
- **投票中の離脱**（2026-06-10 確定）: 離脱者の票は集計から除外し、残った参加者だけで全員一致を再判定する
- **結果表示後のセッション**（2026-06-10 確定）: 各自のペースで閲覧・離脱できる。無人になった時点で削除、作成から24時間でタイムアウト。「もう一度さがす」は新規セッション作成
- **場所指定**: GPS現在地（デフォルト）＋テキスト手動入力の両対応
- **外部API**: Google Places API（飲食店検索・クチコミ・GPS周辺検索）
- **セッション管理**: タイムアウトあり（24時間）。マルチセッション中（結果表示前）に残りがホスト1人になったらセッション終了
- **永続化**（2026-06-10 確定）: セッションはインメモリ管理で割り切る（MVP）。サーバー再起動での消失は許容。Prisma/PostgreSQL は当面未使用とし、将来の履歴機能で再検討

## プラットフォーム方針（2026-06-11 確定）

- **ホスト**: iOS アプリ（Capacitor ハイブリッド、App Store 配布）＋ Web
- **参加者**: Web のまま（QR/リンクでインストール不要の即入室を維持）
- 詳細は `docs/architecture-decisions/ADR-004-capacitor-ios-app.md` を参照
- **App Store 4.2 対策の再検討と確定スコープ**は `ADR-005-stay-capacitor-vs-react-native.md`（RN移行せずCapacitor継続）／審査原稿は `app-store-review-notes.md` を参照

### iOS ネイティブ価値（実装済み・2026-06-18）

- スワイプ投票＋ハプティクス（`@capacitor/haptics`）
- ネイティブ共有シート（`@capacitor/share`）— 招待リンク／決定店の共有
- カメラQRスキャン（`@capacitor/barcode-scanner`）— セッション参加（標準カメラ→Web参加ルートは不変）
